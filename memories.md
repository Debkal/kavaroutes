# Current development rules

- Treat new Driver code and supporting web/API changes as production work. Include real authentication, tenant boundaries, bounded resource use, readable diagnostics, and verification of failure/recovery behavior. Do not leave temporary probes or synthetic fallback identities in the shipped Driver path.
- Pool reusable resources, share in-flight work, cache/memoize stable results, and batch requests when appropriate. Bound caches and queues, preserve failed-operation evidence, and measure third-party request counts.
- The current Driver app is `apps/driver-native`, displaying the dedicated web interface at `https://driver.kavaroutes.com/driver`. The historical feasibility app and its supporting package are preserved at `archive/apps/driver` and `archive/packages/driver-core`; they are excluded from workspaces, CI, and Docker contexts.
- Android builds use `npm run build:apk --workspace @kavaroutes/driver-native`. Bump `apps/driver-native/app.json` version and versionCode for changed distributed bytes. The script syncs the generated Android version fields, verifies metadata, names the APK `kararoutes_driverv<version-without-dots>.apk`, and copies identical bytes to `artifacts/mobile-builds` and `~/lanftp-received`. Never overwrite a distributed version with different bytes.
- Run Android 35 validation with `scripts/emulation/android35.sh` through the installed `~/emulation` environment. Keep temporary emulator test probes out of final packaged APKs. Distinguish emulator evidence from physical-phone/server receipt evidence.
- SQLCipher GPS queue operations must use a keyed connection. Expo's `withExclusiveTransactionAsync` opens another connection; applying a key only to the original connection is insufficient.
- Preserve existing user data and unrelated workspace files. Local commits are authorized; the user pushes Git. Existing VM deployment is authorized and should retain rollback evidence.

- Run `npm run check:project-audit` for the whole-project inventory, decision counts, and archived source hashes. Keep maintained browser doubles under `apps/web/src/test-support`; production builds must pass `npm run check:web-bundles`. Dispatch consumers share `dispatch-queries.ts` keys; normalize absent client filters to null so the history map and exports reuse one trace request. Preserve 5-second disconnected Dispatch polling and 10-second location-status polling.

- Dispatch now uses authenticated business context and explicit persisted memberships/grants. Never restore shared Synthetic persona headers, browser-selected billing/reviewer principals, fixed business IDs in clients/cache keys/setup links, or gateway-injected identities. Cloudflare is only the configured TestPony test-environment exception and the existing platform Admin gate; ordinary businesses require their own account session. Dedicated Firebase business settings are currently unconfigured. See `docs/business-identity-migration-2026-09-29.md`.
- Preserve historical business UUIDs, actor references, receipts, and DriverSession tokens when migrating identity. Provider-account evidence uses bounded pooling/caching; database membership revocation remains immediate. Include protected configuration and mounted-adapter backups in runtime promotions.
