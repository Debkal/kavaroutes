KavaRoutes Driver native shell
==============================

This app is for drivers only. It loads the existing production driver screen at
https://driver.kavaroutes.com/driver on Android and iPhone. A generic business
access screen opens first; drivers enter their business code and separate access
password, then use their own driver login. Dispatch and driver-admin screens are
not part of the native app.

During an active shift, the phone's native location task collects GPS fixes and
posts them to the existing driver shift location-batches endpoint. The Android
foreground service shows a persistent notification. iOS uses Core Location's
background-location mode and indicator. Google Maps opens as a separate app,
leaving the location task running. The web page itself still owns login,
itinerary, trip actions, signatures and sign-off.

The native Android login requests foreground location first, then shows an
in-app Continue button before Android's "Allow all the time" settings screen.
Notification permission is requested just before the shift's GPS service starts so
declining it cannot block sign-in. Grant it to see the ongoing "Driving shift
active · GPS on" notification in the phone's notification bar.

Build prerequisites:
- Node 24.19.0 and npm 11.17.0; run npm ci at the repository root.
- Android: Android SDK/JDK and a configured emulator or phone.
- iPhone: macOS/Xcode, an Apple development team and a connected phone or simulator.
- Expo Go is insufficient for testing background location. Use a native build.

Commands from the repository root:
  npm run typecheck --workspace=@kavaroutes/driver-native
  npm run bundle:android --workspace=@kavaroutes/driver-native
  npm run bundle:ios --workspace=@kavaroutes/driver-native
  npm run android --workspace=@kavaroutes/driver-native
  npm run ios --workspace=@kavaroutes/driver-native

The first three commands validate code and create JavaScript bundles; they do
not produce signed installable packages. The final two prebuild and install a
native development app on a device or emulator. Production APK/AAB/IPA signing
and store distribution require their platform credentials.

For each new standalone Android test APK version, update expo.version and
android.versionCode in app.json, prebuild Android if needed, then run
`npm run build:apk --workspace=@kavaroutes/driver-native`. This builds the
release APK, checks Gradle's version metadata, and copies it to both
artifacts/mobile-builds/kararoutes_driverv<version digits>.apk and
~/lanftp-received/ with the same filename. Version 0.1.1 becomes
kararoutes_driverv011.apk. Use `node scripts/build-driver-native-apk.mjs
--package-only` from the repository root only when the matching release APK
has already been built. A different APK cannot overwrite an existing file
with the same version name; bump the version first.
This project currently signs that release-mode APK with the generated Android
debug key. It is installable for private testing and is not store-ready.

On a real phone, enter the business access credentials, sign in with a driver
account, grant precise/always location,
start the shift, open Google Maps from the trip link, lock and unlock the phone,
then check Dispatch Active Drivers for fresh fixes. Finish the shift and confirm
the Android notification/iOS indicator ends. Also test network loss and return.
Opening Google Maps is expected and does not itself create a tracking alert.
During a test, turn phone location off for over a minute while the shift stays
active, then restore it. Dispatch Active Drivers should show a tracking
interruption and a recovery event; Route History retains the same audit events.
The server records missing fixes, not a claim that the driver caused the gap.
Location is queued in an encrypted device database for retry while the app is
running; a driver session expires after 36 hours and must be renewed by signing
in again. A short phone shutdown preserves the business access session and the
active driver session; reopen Driver after powering on to resume tracking.
Force quitting an iPhone app can prevent further background
delivery until it is reopened. Phone power settings can also affect update
frequency, so a physical test is required before relying on continuous tracking.

The public Driver hostname shows only a generic business access form until a
business-scoped password is accepted. Driver and driver-admin pages and login
APIs require that session. The driver's own login issues a DriverSession; this
token authorizes native background uploads even while the WebView is away.
If it expires, reopen Driver and sign in again. Business driver admins manage
invitations at https://driver.kavaroutes.com/driver-admin in a regular browser,
after the same business access screen. To rotate a business access password on
the VM, pipe the new password into provision-driver-access.py with the accounts
file path, business UUID and code; existing business sessions are revoked.
