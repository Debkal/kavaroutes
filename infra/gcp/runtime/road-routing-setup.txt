# Dispatch road routing

Dispatch opens a planned run, chooses a trip leg and then chooses one of three
route goals. Each choice generates a fresh road route and map. **Shortest
distance / lower toll cost** asks the provider to prefer toll-free roads and
shorter distance; it does not calculate fuel, labor or total trip cost.
**Fastest drive** chooses the lowest estimated duration among the three
proposals; traffic is approximated, not live. **Easiest to traverse** avoids
ferries and favors fewer maneuvers. Alternatives may
use the same roads. The selected *goal*, rather than provider map content, is
stored for the trip leg. The assigned driver receives newly generated directions
for that goal.

The provider is Geoapify Routing, Geocoding, and Static Maps. It is optional at
startup: when no key is configured, the rest of dispatch
and the driver app remain available and the driver can still open basic pickup
to drop-off directions in Google Maps. Route generation itself is unavailable
until the provider is configured. The Google Maps sharing URL remains an
independent driver convenience.

To activate it, create a private environment file at
`/opt/kavaroutes/secrets/geoapify.env` with a single `GEOAPIFY_API_KEY=...`
entry and mode 0600. Docker Compose injects it into the API container. Never
put the key in source or the web bundle. The API requests the static map on the
server and returns PNG data; the browser never receives the provider key.
Geoapify's free tier has a daily credit allowance. Keep required Geoapify and
OpenStreetMap attribution visible on the dispatch map.

The map and directions are guidance for the dispatcher and driver. Google Maps
may recalculate the shared URL, and the URL cannot pin the exact route returned
by Geoapify. Confirm pickup side, vehicle access, road restrictions and live
conditions before driving. The route result is never used as proof of pickup or
drop-off time; the existing driver action receipts record those events.
